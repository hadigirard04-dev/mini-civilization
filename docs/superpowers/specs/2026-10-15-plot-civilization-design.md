# 地块级文明重写设计（Spec）

- 日期：2026-10-15
- 状态：对话设计已获批准；本文为待实施 spec，实施前需用户复核
- 施工分支：`feat/plot-civilization`｜参照点：tag `v0.5`（= 线上部署版本 `c1b4de5`）
- 影响范围：**替换「大陆文明演化」模式的模拟核心与渲染层**；自由沙盒、首年生存保持不变
- 参照游戏（本次核实到的机制，2026-10-15 直读）：
  - **Cities: Skylines**（Paradox 官方 wiki `Zoning` / `Land value`）：区域只能划在离路 4 格内；长出的建筑正面必须紧贴道路；玩家不能直接放住房；住得好的建筑会升级；地价由服务、公园、教育、交通抬升，被污染与犯罪压低；高级住宅/商业只在高地价地块生成。
  - **Banished**（banished-wiki.com `Market`）：市场覆盖 90 格直径，范围内居民优先从市场取货，不必远行，因此工作效率更高。
  - **Manor Lords**：地块沿已建/规划道路拉出、正面朝街；市场覆盖半径卡住升级。**仅二手来源**（指南站与官方 wiki 搜索摘要，官方 wiki 正文 403 未读到），仅作旁证。

## 1. 为什么要重写（机制诊断）

| 现象 | 证据（2026-10-15） |
| --- | --- |
| 城市形态由唯一变量决定 | `simulation.ts:940 findBuildSpot`：一切按"到地图几何中心（`size/2`，永不改变）的距离"分环；住宅 `spread*0.7`、高楼 `spread*0.45`、农田 `spread+5`、工业 `spread+9` |
| 路是结果的产物，不是骨架 | `simulation.ts:1242`：建筑落成时沿 `findPath(地图中心 → 该建筑)` 铺路（0.2 石/格）→ 路网必然是放射蛛网 |
| 形状被格点锁死 | 候选格 `x%4==0 || y%4==0` 直接排除 → 建筑只能落在 3×3 小块，画面必为等间距方格阵列 |
| 位置没有对错 | 无分区、无服务覆盖半径、无地价、无需求；河流/海岸/山地/矿产不参与形态 |
| 玩家不是主角 | 时代门槛是"自动会达成的量"（人口要求 20/28/40/60、知识与材料自动涨）：200× 实机第 2382 天（第 6 年）即到现代都市，此时仅 271 人 / 77 建筑 |
| 人口结构失真 | 寿命 64–84 游戏年，5 个时代 6 年走完 → 4000 天长测死亡 0；迁入 1356 vs 出生 209（迁入占 86%） |
| 后期无内容 | 现代都市后 `eraRequirements` 返回空；知识攒到 17 万无用途；住房容量 4668 对人口硬顶 1800 无意义 |
| 上限不是设计选的，是性能选的 | 实测 1448 人 / 279 建筑时 47 FPS、实速 38.7×（目标 200×）→ 1800 人硬顶源于逐人模拟 |

**结论**：城市形态不合理不是一个参数问题，而是整条机制的链条缺失。同类游戏的链条是「路网 → 临路地块 → 分区 → 服务覆盖/地价 → 需求决定长什么 → 建筑按本地条件升级」；本项目只有"离中心多远"一环。重写即为补上这条链，并借聚合模型解除人口上限。

## 2. 目标与非目标

**目标**

1. 城市形态由**路网 + 地块规则**生成，可解释、受地形影响、每个聚落形状不同。
2. "文明发展"由**城市形态指标**驱动，快进不能自动通关。
3. 解除人口上限（帧预算从"逐个体模拟"改为"区块结算"），人口可达数千至数万。
4. 目标形态是**多聚落文明**：多个定居点各自生长、道路相连，时代推进解锁转运与都市带。

**非目标（本期明确不做）**

玩家画路/划区的规划 UI；可变多边形地块；战斗/外交/科技树；现实人口数据校准；自由沙盒与首年生存的任何改动。

## 3. 已定决策（对话确认，不再重议）

1. 直接替掉现有「大陆文明演化」模式（旧 v3 文明档不迁移）。
2. 居民**完全聚合**：地块账本是真相源，人只是按人口比例生成的动画采样。
3. **全自动规划器**（模拟自己布路、划区、放服务）+ 玩家只调**政策滑杆**。
4. **地块 = 8×8 瓦片固定区块**（256×256 → 32×32 = 1024 块）。
5. 目标形态**多聚落文明**；第一个可玩切片先只做单城，但数据模型从第一天就是多聚落。

## 4. 领域模型

### 4.1 常量

| 名称 | 值 | 说明 |
| --- | --- | --- |
| `TILE` | 256 | 地图边长（瓦片），沿用 |
| `BLOCK` | 8 | 区块边长（瓦片） |
| `BG` | 32 | 区块网格边长 → 1024 块 |
| `TICKS_PER_DAY` | 60 | 沿用（1× 下 1 游戏日 = 1 秒） |
| `DAYS_PER_YEAR` | 365 | 沿用 → `CIVIC_YEAR_TICKS = 21900` |

### 4.2 Block（区块）

区块是**唯一账本单位**。坐标为 `(bx, by)`，覆盖瓦片 `[bx*8, bx*8+7] × [by*8, by*8+7]`。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `terrain` | 主导地形 id | 由 64 瓦片投票得出；`buildable` = 非水域、非山地、非陡坡 |
| `hasWater` / `hasForest` / `hasOre` | boolean | 水文/林地/矿脉特征（决定农业、伐木、采矿资格） |
| `zone` | `none｜residential｜agriculture｜industry｜civic｜park` | 由规划器分配 |
| `density` | 0–4 | 建设强度：空 / 低层 / 多层 / 高层 / 塔楼 |
| `population` | number（可小数） | 该区块居住人口（聚合账本） |
| `jobs` | number | 该区块提供的岗位 |
| `buildings` | `{kind, tx, ty, level}[]` | **仅渲染用**的建筑描述符（瓦片内偏移） |
| `covered` | `{market, school, clinic, park, power, water}` 0–1 | 服务覆盖强度 |
| `landValue` | 0–1 | 派生值（见 7.5） |
| `pollution` | ≥0 | 本块污染负荷（工业产生，自身为源） |
| `construction` | `{kind, progress}｜null` | 在建项（材料已扣，进度按日推进） |
| `claimedBy` | settlementId｜null | 归属聚落 |

### 4.3 道路：区块之间的**边**模型

道路不再占用瓦片，而是**区块之间的边**——这样"临路"是可判定的布尔量，路网就是一张 1024 节点、约 2112 条边的图，规划器、物流距离、居民动画寻路全部复用这张图。

- 竖边 `V[bx][by]`：连接块 `(bx-1,by)` 与 `(bx,by)`；横边 `H[bx][by]`：连接块 `(bx,by-1)` 与 `(bx,by)`。
- `roadAccess(block)` = 该块四条边中至少一条是路。
- 跨水边可建**桥**（造价 = 石 × N + 钢 × M，随跨度），建桥后仍算连通。
- 道路分级：`path`（土路，早期）/ `street`（街） / `avenue`（大道，时代 3+）。等级影响物流系数与动画速度，不改变连通性。
- **建造顺序**：规划器先修路（扣材料），**只有 `roadAccess` 的块才能被分配住宅/工业/公共/公园区**（农业区例外，见 6.3）。

### 4.4 Settlement（聚落）

| 字段 | 含义 |
| --- | --- |
| `id`, `name`, `centerBlock` | 身份与中心 |
| `blocks: Set<blockIdx>` | 已归入本聚落的块 |
| `population`, `jobs`, `housing` | 聚合统计（由块汇总，不独立存储真相） |
| `linkedTo: Set<settlementId>` | 路网可达的其他聚落（时代 3+ 才允许转运） |
| `foundedTick` | 建城时间（用于纪事） |

### 4.5 全局账本（替换现有 `stock`）

`food / wood / stone / steel / electricity`：各含 `stock`、`productionPerDay`、`consumptionPerDay`；`storageCapacity`（粮仓总容量，用于时代门槛与溢出损耗）；`population = {children, adults, elderly}`；`knowledge`；`births / deaths / immigrants` 累计计数（人口账守恒用）。

### 4.6 不变量（必须有对应测试）

| 编号 | 不变量 | 断言时机 |
| --- | --- | --- |
| INV1 | `20 + births - deaths + immigrants = Σ block.population`（±1 人四舍五入容差） | 每 200 游戏日 |
| INV2 | 五种资源储量 ≥ 0，且 `stock` 变化与流量账一致 | 每游戏日 |
| INV3 | 所有 `residential / industry / civic / park` 块 `roadAccess = true` | 每次规划后 |
| INV4 | 工业块与住宅块**不直接相邻**（规划器不变量，玩家不直接改区，故恒成立） | 每次规划后 |
| INV5 | 无 NaN / Infinity（人口、地价、覆盖、资源） | 每 200 游戏日 |
| INV6 | 存档往返等价（含 `rngState`，反序列化后逐字段比较） | 单测 |
| INV7 | `era` 单调不减；跨代必须满足 8 节的全部门槛 | 长测 |
| INV8 | `0 ≤ covered.* ≤ 1`、`0 ≤ landValue ≤ 1`、`pollution ≥ 0` | 单测 + 长测 |

## 5. 结算循环

| 频率 | 内容 | 成本预算 |
| --- | --- | --- |
| 每 tick | 在建项进度推进；动画所需的少量状态（居民采样取景） | < 0.05 ms |
| 每游戏日 | 产出/消费结算（按块聚合）、资源入库、人口出生/死亡结算 | < 0.5 ms |
| 每 5 游戏日 | 污染扩散 → 服务覆盖 → 地价 重算，随后跑 **规划器循环**（选址/路网/分区/服务/升级，见 6 节） | < 2 ms，且分帧摊平 |
| 每 30 游戏日 | 迁入结算、时代门槛检查、纪事与统计采样 | 可忽略 |

目标：1000 块、人口 20000 时，单帧模拟耗时 ≤ 2 ms，200× 仍能维持目标倍速（对照 v0.5：1448 人时已掉到 38.7×）。

## 6. 规划器（自动市长）

一段**纯函数式、可单测**的决策逻辑，输入账本快照，输出"待执行动作列表"（修路 / 分区块 / 建公共服务 / 升级 / 建桥）。按固定顺序执行，便于测试与解释。

### 6.1 选址（多聚落）

对每个未被占用的块算定居点评分：
`score = 0.30×淡水可达 + 0.20×林地 + 0.20×可耕平地 + 0.20×矿脉邻近 + 0.10×与既有聚落的距离适中`（太近则跳过，避免聚落粘连）。
规则：首聚落取最高分；当主城人口 > 阈值（初值 3000）且存在 `score ≥ 0.6` 的空位时，规划器申请建新城（需物质储备达标）。

### 6.2 路网

1. 中心块沿四个方向延伸**主干道**（`avenue`，时代 3+ 升级），优先指向：本聚落的资源点（矿/林/大片平地）、相邻聚落、水岸。
2. 干道每延伸 K 格（初值 4）分叉出**支路**（`street`），支路再短距离分岔（`path`）。
3. 跨水/山地必须绕行，或花材料建桥（只在"绕行距离 > 3 倍直连距离"时建桥）。
4. 新块纳入聚落的判据：与已有块相邻且已 `roadAccess`。
5. 已有路网可被**升级**（`path → street → avenue`）而不是重画，保持形态连续。

### 6.3 分区（谁长在哪）

候选：`roadAccess = true` 且 `zone = none` 的可建块。对每类分区算分：

- **住宅**：`+ 市场覆盖 + 学校 + 公园 + 地价 − 污染 − 工业邻接`，且必须 `roadAccess`。
- **农业**：`+ 可耕平地 + 淡水邻近 + 远离中心`；**允许不临路**（田地不需要路），但产出按物流系数打折（见 7.3）。
- **工业**：`+ 矿脉邻近 + 干道邻接 + 远离住宅人口重心`；**硬约束：不得与住宅块相邻**（若唯一候选都相邻，则本周期不建工业）。
- **公共**（市场/学校/诊所/电站/水厂）：由 6.4 决定位置，不作为"区"参与打分。
- **公园**：住宅密集且地价低的块，用于抬地价。

### 6.4 服务补齐

按"覆盖缺口 × 受影响人口"排序：先算每块 `covered.market/school/clinic/park`（半径内服务建筑数量 × 距离衰减），再挑缺口最大的位置放对应服务建筑。电站按电力缺口放，水厂按淡水可达性放。

### 6.5 升级

块住房升级只由**本地条件**决定：`density` 提升需同时满足 `landValue ≥ 阈值(1→2:0.35, 2→3:0.5, 3→4:0.65)`、`covered.power ≥ 0.9`（3 级以上）、材料充足、且该块人口 ≥ 当前容量 × 0.8。**不再使用全局人口数**。

### 6.6 政策滑杆

五档：`均衡 / 粮食 / 扩张 / 研究 / 宜居`。政策只改权重与系数（一个 `Policy` 表），不新开分支逻辑，便于测试与调平衡。示例：粮食 ×1.25 农业产出、扩张优先建路与新块、宜居加权公园与诊所、研究加权学校与知识。

## 7. 经济与人口（初值，全部放 `src/sim/config.ts`，由用户调平衡）

> 下列数字是**起点值**，不是校准结果；改它们不需要改代码。

### 7.1 产出（每游戏日 / 块）

| 类型 | 基础产出 | 修正 |
| --- | --- | --- |
| 农业块 | 30 粮 | × 机械化(1 + 0.5×电力覆盖) × (1 + 0.25×农舍数) × 物流系数 × 政策系数 × (1 − 污染×0.3) |
| 林地块 | 4 木 | × (1 + 0.15×工坊数) × 物流系数 × 政策 |
| 矿块 | 3 石 + 矿脉缩减 | 有限矿藏（沿用 `oreReserve` 思路，改为按块存量） |
| 工业块 | 1.2 钢 | 消耗 2 木 + 1.5 石 + 4 电/日 |
| 电站 | +12 电 | 消耗 1 木、0.5 石/日 |
| 学校 | +知识 | 按岗位数 |

### 7.2 消费

人口消费粮食：成年 0.35/日、未成年 0.20/日、老年 0.28/日（相对变化由政策与饥荒状态修正）。城市与工业按 7.1 耗电耗料。**调平衡目标**：1 万人口、食物基本自给时，农业块不超过已开发块的 30%。

### 7.3 物流系数（让位置有意义）

按"到最近仓储/市场的**路网边距离**（BFS 跳数）"分档：`≤8 边 = 1.00`、`≤16 = 0.85`、`≤24 = 0.70`、`>24 = 0.55`；未接入路网的农业块 = 0.45。这一项是"选址有对错"的核心机制。

### 7.4 住房容量与人口

- 区块住房容量：`density 0/1/2/3/4 → 0 / 30 / 70 / 150 / 320` 人。
- **出生**（每游戏日）：`rate = 0.00020 × 粮食安全 × (1 + covered.clinic) × 住房余量系数`，且聚落成年人口 ≥ 2；写入 `births`。
- **死亡**（每游戏日）：`rate = 0.00008 × (1 + 6×老年占比) × (1 + 0.5×污染) × (1 − 0.4×covered.clinic)`，写入 `deaths`。**目标**：让 4000 天内出现可观察的代际更替与人口波动（v0.5 该项恒为 0）。
- **迁入**（每 30 日）：`吸引力 = 0.35×平均地价 + 0.25×岗位余量比 + 0.25×粮食安全 + 0.15×连通度`；`月迁入 = round(吸引力 × 人口 × 0.03)`，再受住房余量、岗位余量、口粮、外部人口池（沿用 `migrationPool`）限制。

**节奏设定（本模式的"时间尺度"是设计选择，与 v0.5 不同）**：目标是从 20 人原始聚落长到 1 万人口用 **30–60 游戏年**（200× 实机约 5–9 分钟），其中前期以迁入为主、后期外部人口池耗尽后靠自然增长（净 2–5%/年）继续扩张。为此"游戏年 = 365 天"仅作为历法单位，时代推进由形态指标决定（8 节），不再被天数或人口数字绑定。

### 7.5 污染与地价

- 污染：工业块为源（1.0），按块距离衰减扩散（1 格 0.5、2 格 0.25），每 5 日重算。
- 地价：`landValue = clamp(0.25×covered.market + 0.20×covered.school + 0.15×covered.clinic + 0.20×covered.park + 0.10×水岸 + 0.10×(1−污染) − 0.15×工业邻接, 0, 1)`。

## 8. 时代门槛（形态指标，取代"攒数字"）

| 时代 | 门槛（全部满足才升级） |
| --- | --- |
| 农业聚落 | ≥6 个农业块；仓储容量 ≥ 30 天口粮消耗 |
| 繁荣城镇 | 路网边 ≥60；市场覆盖住宅人口 ≥70%；住房平均 `density ≥ 2` |
| 工业城市 | 工业块与住宅块相邻对 = 0；电力覆盖 ≥90%；累计钢产量达标（初值 2000） |
| 现代都市 | 地价 ≥0.6 的住宅块 ≥24；≥2 个聚落路网连通（都市带） |

每代解锁新的空间组织方式：道路等级上限、区块密度上限、新服务类型（学校/诊所/电站/水厂）、枢纽建筑（市场→交易所）。

## 9. 渲染与 UI

- **地形层**：沿用 `render/terrain.ts`（离屏缓存）。
- **区块层**（新）：分区底色（可关）、建筑按 `kind/level` 绘制（帐篷→木屋→砖房→公寓→塔楼，沿用 v0.5 美术资产思路）、道路按边绘制（宽度随等级）。
- **居民采样层**：按块人口比例生成有限数量动画实体（上限约 300），沿区块图与道路边行走、搬运、施工，保留"看得见人"。
- **图层开关**：分区 / 服务覆盖 / 地价 / 污染。这是"看懂为什么长在这"的关键。
- **侧栏**：聚落列表（人口、岗位、住房、覆盖、连通）、政策滑杆（5）、时代门槛进度（形态指标形式）、人口结构曲线、纪事。
- 快进保持 1×–200×；相机沿用 v0.5 的跟随/总览/大陆三档。

## 11. 测试策略

**单元/机制测试（新）**

- 区块账本：产出/消费守恒（INV2）、流量与储量一致性、污染扩散、地价边界（INV8）。
- 规划器：`roadAccess` 判定、跨水绕行/建桥、住宅与工业不相邻（INV4）、服务覆盖计算（距离衰减正确）、升级阈值。
- 人口：出生/死亡/迁入各自与合并后的守恒（INV1）、迁入受限条件。
- 时代：门槛逐项断言（INV7），且"不满足时不得升级"。
- 存档：往返等价（INV6）、v3 文明档拒绝加载、沙盒/首年档仍可加载。

**集成长测（重写）**

- 4000 天多聚落文明：INV1/2/5/7 全程成立；至少达成 3 个聚落与工业城市；输出关键指标（人口、聚落数、路网边数、平均地价）供回归对比。
- 性能基准：1000 块 × 2000 tick 的墙钟时间（对照 v0.5 的 benchmark 脚本）。

**验收（人工）**

- S1 起每片留一张真实截图；"像不像城市"由用户判断，机器只保证不变量。

## 14. 风险与止损

| 风险 | 对策 |
| --- | --- |
| 范围膨胀（多聚落 + 转运 + 时代） | 切片门禁；S1 不达标立即停下复盘，不往下堆 |
| 完全聚合后画面"人味"下降 | 区块建筑按等级渲染 + 300 实体动画采样 + 道路上的搬运表现 |
| 形态门槛失衡导致卡关或速通 | 全部门槛与系数集中在 `config.ts`，由用户调；长测输出关键指标供回归 |
| 旧档作废引起困惑 | README 明确 v4 不兼容 v3 文明档；加载时给出明确提示；tag `v0.5` 可回滚 |
| 重写期仓库不可用 | 施工在 `feat/plot-civilization`；master 保持 v0.5 可玩可部署 |
